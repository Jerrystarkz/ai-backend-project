1. System Overview
The Local RAG Assistant is a full-stack local Retrieval-Augmented Generation (RAG)
 and tool-calling agent application built with FastAPI, PostgreSQL, Ollama (llama3.2),
  and Streamlit. It runs entirely on local infrastructure, serving the FastAPI backend
   on port 8000 and the Streamlit user interface on port 8501.

The platform supports PDF and plain-text ingestion, boundary-aware overlapping text 
chunking with automated page tracking, vector similarity search, local Python tool 
invocation, progressive token streaming, and session-persistent chat history stored in
 PostgreSQL.

5. Core Pipelines & Operational Workflows
5.1 Document Ingestion & Boundary-Aware Chunking (POST /documents/upload/)
Reads raw bytes from the uploaded .pdf or .txt file via FastAPI UploadFile.
For PDF documents, extracts text page-by-page (1..N via PdfReader); for text files,
 decodes UTF-8 strings.
Splits text using chunk_text_with_overlap(chunk_size=800, overlap=150), normalizing whitespace,
 snapping split boundaries to sentence or word breaks in the second half of the window,
  and retaining 150 characters of overlap across consecutive chunks.
Prefixes each chunk with [File: ... | Page: ... | Chunk: ...], computes an embedding
 via generate_embedding, and stores page_number and chunk_metadata through crud.create_document_with_chunks.
5.2 Agentic Tool Execution & Token Streaming (POST /documents/agent/stream/)
Persists the incoming user message to chat_history under the active session_id.
Queries Ollama (llama3.2) with TOOLS_SCHEMA (stream=False) to inspect whether a
 tool call is required.
When requested, executes the corresponding local Python function: get_document_count(db),
 calculate_expression(expression), or search_document_content(keyword, db).
Appends the tool output to the message list and streams the final answer (stream=True)
 through FastAPI StreamingResponse (text/plain; charset=utf-8).
Uses a dedicated SessionLocal() inside the stream generator to accumulate all chunks
 and save the complete assistant response (with an empty-output fallback guard) upon stream completion.

5.3 Semantic Vector Search & Grounded Q&A (/search/ & /ask/)
Both endpoints embed the incoming query with generate_embedding and rank stored chunks
 by cosine_similarity. The /ask/ endpoint additionally retrieves recent session turns via get_session_history,
  constructs numbered context blocks, generates a grounded answer via generate_grounded_answer,
   saves both conversation turns, and returns source snippets and similarity scores.

 Boundary snapping concentrates most chunks inside the 601–800 character window, with

7. Local Runtime & Operations
Database Prerequisites: Ensure PostgreSQL is running with tables documents,
 document_chunks (including page_number INTEGER and chunk_metadata JSONB), 
 and chat_history, and ensure Ollama is running locally at http://127.0.0.1:11434 with llama3.2 pulled.
